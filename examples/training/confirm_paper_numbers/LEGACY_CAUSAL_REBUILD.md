# Legacy Causal Llama Full-FT Rebuild

This document freezes the reproducibility contract for the corrected
Llama-3.2-1B full-fine-tuning rebuild. It applies the effective training behavior of
the legacy ELLMTrees causal-LM runner to the fresh WeightTraits trees and task
assignments. It does not redefine the historical ELLMTrees cohorts or change the
paper's analysis.

## Protocol contract

The authoritative ordinary-cohort config is
`llama32_1b_full_finetune_legacy_causal_2000.yaml`. The matched no-translation
config in `../translation_holdout_20260803/` extends it and changes only the model
family/output root and assigned task sequence.

- Base model: `meta-llama/Llama-3.2-1B`, pinned to revision
  `4e20de362430cd3b72f300e6b0f18e50e7166e08`.
- Method: full fine-tuning, causal LM, BF16 model and training.
- Loss: completion tokens only. Prompt tokens and padding labels are masked.
- Sequence length: `1024` is the combined prompt-plus-observed-target-plus-EOS
  window for every task family. It is not a target-length or completion allocation.
  Targets retain their natural observed lengths and are tokenized first; the prompt
  occupies the remaining window. The legacy eight-token prompt reserve is
  preserved.
- Effective padding: right padding to a multiple of 8. The old tokenizer object was
  nominally configured for left padding, but its custom collator manually appended
  pad IDs, zero attention-mask values, and `-100` labels on the right. Right padding
  in WeightTraits reproduces the batches that were actually trained.
- Randomness: trainer seed `42`. Dataset caps use the exact legacy, non-streaming
  rule: if a sized split is larger than its cap, run the full map-style
  `Dataset.shuffle(seed=42).select(range(cap))`; otherwise preserve source order.
  The caps are 10,000 training rows and 1,000 evaluation rows. A streaming or
  bounded-buffer shuffle is not equivalent and must not be used.
- Optimization: exactly 2,000 required steps; train/eval batch size 8; gradient
  accumulation 4; learning rate `2e-5`; 200 warmup steps; weight decay `0.01`;
  max gradient norm `1.0`; evaluation every 250 steps; logging every 10 steps; no
  gradient checkpointing.
- Stopping and saving: early stopping is disabled and `require_max_steps: true`
  makes a run that does not reach step 2,000 fail. Production launches must not
  pass `--override-max-steps`. Trainer resume checkpoints are not part of the
  legacy contract (`save_strategy: "no"`).
- Rendering: prompts and natural-language targets come from
  `dataset_formats_legacy_causal.yaml`. Classification targets are human-readable
  labels; BoolQ uses `yes`/`no`; multiple-choice QA uses the full choice text and
  retains the legacy fallback to the answer-key string if lookup fails.

### Executable protocol versus manuscript description

The archived executable Llama manifests and runner use a 1,024-token combined
window, train/eval batch size 8, and gradient accumulation 4. The current
manuscript describes a 640-token maximum, batch size 1, and gradient accumulation
32. This rebuild follows the executable protocol because its purpose is to replace
artifacts generated by that code path. The mismatch is recorded here as a
reproducibility discrepancy; it must not be silently harmonized by changing either
the rebuild config or manuscript text.

## Cohort scope

The ordinary fresh cohort is the 50-tree, 641-node assignment set recorded in
`assignment_summary.json`. Its corrected outputs live under
`outputs/confirm_paper_numbers/llama32_1b_full_finetune_legacy_causal_2000/`.

The matched no-translation cohort is also 50 trees and 641 nodes. Its
`matched_assignment_summary.json` preserves the 479 already-non-translation rows
from the ordinary fresh cohort and replaces its 162 translation rows with
classification, QA, or summarization assignments. It uses the identical tokenizer,
sampling, rendering, optimization, and stopping contract. Its corrected outputs
live under
`outputs/translation_holdout_20260803/llama32_1b_full_finetune_legacy_causal_2000/`.

The historical `../ELLMTrees/outputs/runs_llama1b_base_full_ft_notrans` cohort was
already trained by the old causal runner. It is a reference cohort, not a target
of this WeightTraits relaunch.

### Fresh-pool caveat

This is an exact legacy *training-method* rebuild for the 35 datasets shared with
the old runs, not a dataset-pool-identical replay. The fresh 36-dataset pool contains
SetFit/TREC-QC and omits AESLC. The actual legacy ordinary manifests contained AESLC
(five assigned nodes) and no TREC-QC; the old handler registered under `trec` also
redirected to GLUE/MRPC rather than SetFit/TREC-QC. Therefore results involving the
fresh TREC-QC assignments must be described as an analogous extension of the legacy
protocol. Reconstructing the exact old dataset pool would require a separate
assignment change and is outside the immediate rerun.

### 2. Build one shared, non-streaming legacy cache

On Wright, the checked-in job is the required entry point:

```bash
sbatch --export=ALL,REPO=[WEIGHTTRAITS_REPO] \
  scripts/slurm/cache_legacy_causal_training_data.sbatch
```

The job deliberately builds the destination cache in two phases. It loads the 35
datasets shared with ELLMTrees from the historical Hugging Face datasets cache
with both datasets and Hub offline modes enabled. It then fetches only the fresh
SetFit/TREC-QC extension online at the commit pinned in the registry. The job
writes a separate receipt for each phase and a combined 36-dataset summary. Do
not replace this with one unconstrained online load: that would make the shared
datasets depend on current mutable repository state.

Both phases use `legacy_subsample`, seed 42, train limit 10000, and eval limit
1000. Do not add `--streaming`, `seeded_shuffle`, a shuffle buffer, or text-length filters.
Use a new cache root, or use `--overwrite` only when intentionally replacing every
split in a known incorrect cache. The cache summary must be valid, identify
`legacy_subsample` and seed 42, and have no dropped or filtered rows. Each split's
metadata records registry/format fingerprints, source split fingerprint and row
count, and cached JSONL row count and SHA-256; preserve those metadata files with
the cache. The checked-in
`legacy_causal_seed42_cache_source_receipt.json` freezes all 72 metadata records
from cache job `167743`. Every training row verifies that receipt's SHA-256, the
current registry and format fingerprints, each source fingerprint and row count,
and the cached JSONL bytes before training. A cache rebuilt from a different
mutable source revision therefore fails even if it uses the same seed and caps.

Each node writes immutable `provenance.json` before model training and a terminal
`completion.json` only after the required model or merged artifact is durable.
Before loading a non-root parent, the executor verifies the planned parent row,
effective data and trainer overrides, runtime, completion receipt, and a recursive
SHA-256 of the parent artifact. The provenance also anchors the complete
WeightTraits Python source receipt. It refuses unreceipted, partial, completed,
wrong-source, or wrong-protocol output directories before appending any
output-local log event.
