# Audit Protocol

WeightTraits should make it boring to answer: what changed, why do we trust it, and how close is it to the ELLMTrees result?

## Audit Types

Source audit:
- Count and classify old scripts, modules, configs, tests, and paper files.
- Map every old paper-critical script to a new package module or an explicit retirement reason.

Data audit:
- Record manifest digests.
- Record checkpoint/result availability.
- Record run sets used for every comparison.
- Keep generated heavyweight artifacts out of Git unless deliberately promoted.

Numerical audit:
- Store regenerated metrics as CSV/JSON.
- Compare against frozen ELLMTrees outputs with explicit tolerances.
- Flag missing reference data separately from failed comparisons.

Statistical audit:
- Run Python aggregation and R cross-checks.
- Record formulas, grouping variables, confidence interval method, and package versions.
- Treat R as the paper-facing regression check.

Cluster audit:
- Require dry-run output before submission.
- Require explicit run lists for Slurm arrays.
- Record job IDs, cluster, partition, run list, git commit, and expected outputs.
- Never use stale "catch-up everything" tables as direct submit input.

Paper audit:
- Every figure and table must have a registry entry.
- Every registry entry must name source command, source data, output file, and expected digest or tolerance.
- Paper build should fail loudly when a registered artifact is missing.

## Result States

- `reference`: copied or read from ELLMTrees for comparison only.
- `rebuilt`: generated by WeightTraits from declared inputs.
- `verified`: rebuilt and compared to a reference or independent invariant.
- `provisional`: useful but missing a required check.
- `excluded`: intentionally not used in paper claims.
